# Workflow Evaluation Methodology

## Purpose

Evaluate a Mac creator tool by completing realistic tasks and recording observable evidence. The method is designed to reduce feature-list bias and make comparisons reproducible.

## Test setup

For each run, record:

- Date
- macOS version
- Mac model / chip / memory
- Display configuration
- App version
- Input devices
- Recording resolution and frame rate
- Whether other high-load apps were running
- Export preset
- Any network-dependent features used

## Procedure

For each workflow:

1. Define one concrete task before opening the app.
2. Start a timer when the task begins.
3. Complete the workflow without changing the success criteria.
4. Record failures, retries, workarounds, and interruptions.
5. Export or publish the final result when the workflow requires it.
6. Record total elapsed time.
7. Add qualitative notes only when tied to an observable event.

## Suggested workflows

### Product demo
Record a 3–5 minute product walkthrough, add at least one zoom/focus treatment, trim mistakes, and export.

### Tutorial / documentation
Record a step-by-step tutorial with narration, captions or transcript handling, and a final export.

### Coding walkthrough
Record an editor plus terminal/browser workflow, including text readability and cursor movement.

### Meeting / interview
Record a long session with system audio and microphone, then verify synchronization and recovery.

### Long-form course
Record a longer session and test project stability, editing responsiveness, and export duration.

### Short social clip
Create a short 30–90 second clip from capture through final export.

### Multi-display
Record or switch between displays and verify framing, scaling, and export consistency.

## Evidence rules

- Do not invent scores.
- Preserve raw notes where possible.
- Distinguish measured values from subjective impressions.
- Re-run failed tests before treating a failure as persistent.
- Record material commercial relationships in the disclosure field.
- Do not present affiliated evaluations as indepent third-party endorsements.

## Scoring

A simple 1–5 scale may be used only after the workflow has been completed:

- 1 = workflow blocked or requires major workaround
- 2 = significant friction
- 3 = usable with noticeable friction
- 4 = smooth with minor friction
- 5 = unusually efficient / reliable

Always retain the underlying evidence next to the score.
